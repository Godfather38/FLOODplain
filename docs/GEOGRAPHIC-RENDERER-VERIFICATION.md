# Corrected vector/voxel renderer: delivered module and verification

This is the renderer module checkpoint, not a claim that the entire FLOODplain app or solver coverage is complete. UI integration is described in [GEOGRAPHIC-RENDERER-INTEGRATION.md](GEOGRAPHIC-RENDERER-INTEGRATION.md). No UI-owned files were changed by this worker. The old rejected raster prototype is preserved in commit 8d7a365; the corrected source no longer imports its raster-texture helper or requests raster basemap tiles.

## Implemented

- OpenFreeMap `/planet` TileJSON and real vector-tile geometry, decoded with pinned PBF/vector-tile libraries. Roads, land, permanent water, buildings and labels have source features/attributes and distinct styling. Composite IDs prevent cross-tile OSM ID collisions. Requests are bounded to four concurrent and a 48-tile memory cache. No account, key or paid service.
- Solid native terrain: 2,968,500 real 10 m subgrid elevations matching 29,685 native cells. A bounded 600 × 600 m original 1 m USGS Pima County DEM window is additionally available around cell 9344. Close-up detail is loaded lazily at zoom 18; it is NOT full-region 1 m coverage or 1 m flood computation.
- Camera-centred terrain LOD with an 80,000-instance budget. Both terrain and native water use the same fixed-origin metric altitude scale. A startup camera-extent bug and approximately 10% altitude-scale mismatch in the host helper were corrected.
- Water geometry from native selected-hour `zs`, not mean terrain plus mean depth. Colors/readout retain full-cell mean depth in metres/feet. Fine terrain intersects the native water plane. At coarse LOD, an explicitly native-cell-supported cap preserves wet-cell visibility; it is not a resolved wet footprint. The displayed note identifies the overview support.
- Cosmetic standing water highlights, no moving height/velocity/advection. Reduced motion freezes animation, hidden/inactive view stops its timer, animation capped at 24 fps. No reflections/shadows requiring extra scene renders.
- Flat/3D use one geographic map, source feature set, water model, selected cell and frame; `setViewMode` changes view rather than creating a second map. Flat uses exact native cell footprints at the geographic plane. Route lines/markers/actions are mirrored from the UI's actual route layer; no route risk is calculated from graphics.
- Shared-state constructor argument, current-request check, Promise-returning update, geographic viewport synchronization, existing selection callback and explicit disposal. UI remains acknowledgment owner. Missing-frame failure clears water and popup; outside-cell taps report unavailable coverage. `off` and `hand` do not show stale SFINCS water.

The terrain material's map decoration is generated by this renderer from the same decoded geographic features, not obtained as a pre-rendered raster map. Labels remain screen-sized vector symbols and are not baked into this material. Geographic source identities remain available. This rendering design still needs user visual acceptance; do not describe that acceptance as already obtained.

## Reproduction

Install the versions recorded in `tools/simulation/voxel-runtime-package.json` into the checkout, then:

```
node tools/simulation/build-geographic-view.mjs
node --test test/voxel-water.test.js
node tools/simulation/verify-voxel-browser.mjs
```

The browser script uses installed Chrome, a local server and reduced-motion software WebGL for deterministic screenshots. It does not benchmark a physical phone GPU. Native terrain export scripts consume retained/public data only; neither executes SFINCS.

## Remaining limits and integration work

1. UI owner must mount this renderer for both advanced flat and 3D, call `setViewMode`, and use `viewMode` rather than `active` for requested/displayed state. `hide` is the lifecycle transition out of advanced map. Until that is wired, the original app's flat mode remains its diagnostic raster fallback. No integration edits to the UI worker's files were made here.
2. Final whole-app remote verification, shared-state integration under rapid UI requests, saved-route actions, phone gestures/larger text, and real-device GPU/memory measurements remain. The standalone QA page is only a renderer harness and is NOT the proposed product UI.
3. Fine terrain exists for model-active cells, with a single additional 1 m patch. Terrain outside that native area is not invented. The vector map itself extends farther, while hydraulic coverage stays separate. A general 1 m streaming terrain pyramid is not implemented.
4. The water and terrain appearance has functional evidence but not user approval against the original screenshot, whose pixels were unavailable to both workers. Do not mark the entire visual checklist accepted.
5. Current model support remains 100 m hydraulics with 10 m subgrid and separately approximately 10 m HAND windows. Key required crossings are outside the retained model domain per solver-owner audit; graphics do not repair that. The actual versioned crossing registry is a solver/UI dependency.
6. Full region 1 m terrain, off-channel hydraulic refinement, culvert/depression resolution, calibration, velocities, exact shoreline and measured road depth are not supplied by this module. The new 1 m patch is display data only.
